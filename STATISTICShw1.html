§1 · Problem statement

On the curve y² = x³ + 7 over F₁₇, with base point G = (1, 5) and private key k = 6, compute the toy public key Q = kG. Then slow the algorithm down, explore the statistics of k ↦ kG, and decide whether it behaves like a one-way function or a hash function. Finally, repeat the computation on the real Ethereum curve secp256k1 and compare k ↦ kG with the hash function Keccak-256.

§2 · Background

The points of the curve, together with a point at infinity O, form a group under the chord-and-tangent rule: the line through P and Q meets the curve in a third point, and P + Q is its reflection in the x-axis. Scalar multiplication kG is G added to itself k times, computed by double-and-add. Recovering k from G and kG is the elliptic-curve discrete logarithm problem (ECDLP). secp256k1 (Bitcoin, Ethereum) uses the same equation over a 256-bit prime.

Drag P and Q (or focus a point and use the arrow keys). Bring them together for the tangent case; mirror images give P + Q = O.

§6 · The real curve: secp256k1 and Keccak-256


The toy curve has the same equation y² = x³ + 7 as the curve used by Ethereum, only over a 17-element field instead of a 256-bit prime p = 2²⁵⁶ − 2³² − 977. Because the code of §3 is written with BigInt, the very same pointAdd and scalarMultiply functions now run on 256-bit numbers without losing a single bit. The base point G has prime order n, so the private key k ranges over 1 … n−1.


Ethereum then turns the public key Q = kG into an address by hashing: address = last 20 bytes of Keccak-256(X ‖ Y), with X and Y the two 32-byte coordinates. The pipeline below shows every stage.

§8 · Conclusion


k ↦ kG is a good one-way candidate: deterministic, fast, and on a large curve believed hard to invert. It is not a hash function: it is algebraically structured (homomorphism, symmetry, and the fact that kG gives away (k+1)G), and it has no compression. On secp256k1 simple statistical tests such as the avalanche count cannot tell it apart from Keccak-256, which is exactly why statistics are not enough: the structure tests of §6 separate them immediately. Only the ECDLP argument supports hardness, and that is absent on a 17-element field.



Appendix · Reproducibility


A single HTML file with no dependencies; everything runs in the browser in plain JavaScript. All field and group arithmetic uses BigInt; Keccak-256 is implemented from scratch with 64-bit BigInt lanes and checked at load time against the published values of §6. The data of every figure lives in a <script type="application/json" data-fig-data> block: edit the JSON to change the figures without touching the code. Change G or k (or press Random) to recompute all numbers, plots and tables.
